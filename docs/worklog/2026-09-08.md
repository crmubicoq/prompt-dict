## 결정사항

- **미분류를 `categories` 배열 밖 특수 값으로.** `기타`를 재사용하지 않았다 —
  `기타`는 사용자가 삭제·수정할 수 있는 일반 카테고리이고, 의미도 다르다
  (`기타` = 골라서 넣은 것 / `미분류` = 아직 안 고른 것).
  이 구분이 있어야 T-105에서 정리 대상을 골라낼 수 있다.
  카테고리 삭제 시 소속 프롬프트가 `기타`로 가는 기존 동작은 그대로 뒀다.
- **사이드바에 미분류를 상시 표시.** 카운트 0일 때 숨기면 `updateCategoryCounts` 가
  텍스트만 갱신하므로 0→1 전환에서 버튼이 생기지 않는다.
  클릭 시 필터가 함께 동작해 **T-106도 완료**로 처리했다.
- **제목 자동 제안은 `placeholder` 방식.** `value` 로 미리 채우면 직접 쓰려는 사용자가
  지우고 써야 해서 마찰이 늘고, 본문을 고칠 때 덮어쓸지가 애매해진다.
- **역할 지정 패턴("너는 ~로서")을 감지하지 않고 그대로 제목으로 쓴다.**
  감지하면 동작이 예측 불가능해지고 가장 정보량 많은 줄을 버릴 위험이 있다.
  어차피 제안이고 사용자가 고친다.
- **빠른 등록은 접힘 상태를 기억하지 않는다.** 한 번 펼치면 이후 계속 펼쳐진 채라
  "최소 입력"이 무너진다. **수정 모드만** 고급 필드에 값이 있으면 자동으로 펼친다.
- **불러오기 카테고리 기본값(`기타` → `미분류`)은 T-104에서 함께 결정.**
  `validateCategory` 는 아직 빈 카테고리를 `기타`로 보낸다. T-104로 들어오는 조각은
  카테고리가 아예 없을 텐데, `기타`로 가면 T-105 정리 대상에서 빠진다.
- **T-009 검수 F3·F4는 뒤로.** 인덱스 기반 식별자는 P1 T-113, `removeAll` 의
  `THEME_KEY` 처리는 T-114에서. 근거는 [decisions §6](../decisions/2026-09-08-decisions.md).

## 막힌 부분 · 특이건

### 1. ★ T-101 결함 — 45/45 통과했는데 기능은 안 고쳐져 있었다

카테고리 필수 검증을 해제하고 **45/45 통과**를 받았다. 그런데 실제 사용자는
여전히 카테고리를 골라야 했다.

```html
<select id="prompt-category" required>   <!-- 이게 남아 있었다 -->
```

JS 검증만 지웠고 **HTML 의 `required` 는 그대로**였다. 브라우저가 제출을 막으므로
JS 는 실행되지도 않는다.

**검증이 놓친 이유:** `dispatchEvent(new Event('submit'))` 는 네이티브 폼 검증을
건너뛴다. 테스트는 "JS 코드가 바뀌었다"만 증명하고 통과했다.

→ `form.requestSubmit()` 으로 교체하고 **회귀 항목으로 고정**했다.
T-102에서도 같은 방식으로 검증했다. → [devlog §6.1](../devlog.md)

### 2. Codex 검수 — 파사드가 rejection 을 정규화하지 않았다

호출부는 `if (await save() !== true) { 롤백 }` 형태다.
**어댑터가 reject 하면 이 `if` 에 도달하지 못해 롤백을 통째로 건너뛴다.**
저장은 실패했는데 메모리에는 변경이 남고, 이후 다른 저장이 성공하면 함께 저장된다.

전역 `unhandledrejection` 핸들러가 있어도 소용없다 — **예외를 알릴 뿐 롤백을
실행시키지 못한다.** 안전망이지 해결책이 아니다. → [devlog §4.12](../devlog.md)

파사드에서 `false` 로 정규화하니 **호출부 19곳을 한 곳도 고치지 않고** 롤백이 전부 살아났다.

### 3. `crypto.randomUUID()` 가 보안 컨텍스트 전용

`file://` 은 보안 컨텍스트라 개발 중에는 동작하지만, **P4의 `http:8807` 에서는
`undefined`** 가 되어 ID 생성이 통째로 멈춘다. `getRandomValues` 기반 v4 폴백을 넣었다.
`Math.random` 으로는 떨어뜨리지 않았다. → [devlog §4.16](../devlog.md)

### 4. `parseInt` 4곳이 UUID를 `NaN` 으로 만들 뻔했다

`Date.now()` → UUID 전환에서 생성 지점 5곳만 보면 되는 줄 알았는데,
**읽는 쪽이 더 많았다.** `parseInt` 4곳이 전부 `NaN` 이 되어 카드 클릭·수정 대상 조회·
전체 선택·체크박스 동기화가 한꺼번에 실패한다. 인라인 `onclick` 의 `${id}` 도
따옴표가 없으면 하이픈 때문에 구문 오류가 된다. → [devlog §4.17](../devlog.md)

### 5. `\n` 이스케이프가 실제 줄바꿈으로 박히는 사고 재발

devlog §5.3에 적어둔 함정인데 **`js/ui.js` 에서 똑같이 당했다.**
셸 heredoc 을 거치며 `\\n` 이 `\n`(실제 줄바꿈)으로 들어가 파일이 깨졌다.
`node --check` 가 즉시 잡아냈고, `git checkout` 후 Write 툴 + 플레이스홀더 치환으로 우회했다.

**교훈이 문서에 있어도 같은 도구를 같은 방식으로 쓰면 다시 걸린다.**
백슬래시가 들어가는 코드는 셸을 거치지 않는 경로로 쓰는 것이 확실하다.

### 6. 검증 하네스 실수 4건

- 시나리오 4의 `저장 차단` 항목이 식 안에서 `saveToLocalStorage()` 를 **실제로 호출**해
  검증이 성립하지 않았다 (T-009c-1)
- 관리 목록 컨테이너 id 를 `category-manage-list` 로 잘못 씀 (실제 `category-list-manage`)
- 샘플 데이터에 이미 `개발`·`분석` 이 하나씩 있는 걸 계산에 안 넣어 카운트 기댓값이 틀림
- 백그라운드 검증이 도는 중에 `taskkill /F /IM chrome.exe` 를 해서 4개 시나리오를 날림

전부 코드가 아니라 테스트 쪽 문제였다. **검증이 실패하면 코드를 의심하기 전에
검증을 의심한다.** → [devlog §5.8](../devlog.md)
