## 막힌 부분 · 특이건

decisions 에 "왜"가 있으므로 여기에는 **무엇을 어떻게 재현했는지**만 적는다.

### 1. `escapeHtml` 이 인라인 `onclick` 을 막지 못한다 (T-111 실측)

오늘의 가장 중요한 발견. 태그에 `x'); window.__HIT=1; filterByTag('y` 를 넣고
**`escapeHtml` 을 거쳐** 삽입했더니:

```
브라우저가 본 속성값: filterByTag('x'); window.__HIT=1; filterByTag('y'); ...
>>> 이스케이프했는데도 주입 실행됨? true
```

HTML 파서가 `&#39;` 를 `'` 로 되돌린 **다음** 그 결과를 JS 로 파싱한다.
T-112에서 세 곳(`prompts.js` 130·172, `search-history.js` 66)이 여전히 뚫리는 것을
실측으로 특정하고 주석으로 못 박은 뒤, T-113 이벤트 위임으로 닫았다.
닫은 뒤 같은 페이로드 재시도 → **svg 0건, alert 0건.**
→ [decisions §6](../decisions/2026-09-09.md)

### 2. `<img>` 의 `javascript:` 는 실행되지 않는다 — 내 설명 정정

T-111 보고에서 실행되는 것처럼 말했는데 틀렸다. 실측:

```
javascript: 스킴 img 실행? false
data:text/html img 실행? false
onerror 속성 실행?      true
```

`<img>` 는 브라우징 컨텍스트를 만들지 않아 스킴이 무해하다.
`src=` 의 실제 위험은 스킴이 아니라 **`"` 로 속성을 탈출해 `onerror=` 를 붙이는 것**이고,
그건 `escapeHtml` 이 닫는다. 화이트리스트를 넣은 근거는 다른 데 있다
([decisions §6](../decisions/2026-09-09.md)).

### 3. 150행에서 등록 버튼이 화면 밖으로 (T-104c+d)

```
모달 scrollHeight = 13,705px   clientHeight = 724px
```

목록에만 `max-height: 46vh` + 자체 스크롤 → **13,705 → 1,189px.**
툴바와 등록 버튼이 제자리에 남는다.
**10개로만 테스트했으면 못 봤다** — 목표 규모(150)로 재본 것이 값을 냈다.

### 4. 개수와 미리보기의 디바운스 분리 (T-104c+d)

가상 시간을 끄고 실측한 렌더 비용:

| 행 수 | `buildBulkRows` | `renderBulkPreview` + layout |
|---|---|---|
| 150 | 4ms | 191ms |
| 500 | 11ms | 147ms |
| 1000 | 16ms | 281ms |

입력마다 다시 그리면 타이핑이 끊긴다.
→ **개수는 즉시(동기), 행 렌더는 180ms 디바운스.**
구분자를 고르는 판단이 숫자에 걸려 있어 숫자는 지연시키면 안 된다.

### 5. `renderPromptList` 가 빈 목록에서 카운트 갱신을 건너뛰던 결함 (T-105)

토스트는 `미분류 8개 남음`, 사이드바는 `📥 미분류 (12)`.
빈 목록 분기가 `updateCategoryCounts()` **앞에서 early return** 했다.
필터의 마지막 항목을 분류하면 목록이 비고, 정확히 그 순간 카운트가 멈춘다.
**일괄 삭제에도 있던 결함**이라 함께 고쳤다.

### 6. `parseJSONFile` 이 `thumbnailImage` 도 버리고 있었음 (T-114)

B14는 `notes` 소실로 등록돼 있었는데, 조사해보니 썸네일도 함께 버려졌다.
백업을 업로드 영역으로 다시 넣으면 **둘 다 사라진다.**
필드를 하나씩 옮겨 담는 코드라 새 필드가 생길 때마다 조용히 누락된다.

### 7. 임포트 카운터가 폴백 항목을 안 세던 버그 (T-114)

```js
const originalCategory = prompt.category || '기타';        // 없으면 '기타'로 채운 뒤
if (originalCategory !== '기타' && validatedCategory === '기타')  // '기타'가 아닌 것만 셈
```

**카테고리가 아예 없던 항목이 카운트에서 빠진다.** 폴백으로 떨어졌는데 메시지에
안 잡히니 "N개가 미분류로 분류됨"이 실제보다 적게 나온다.
원본을 채우지 않고 그대로 판정하도록 바꿔, 값 없음과 없는 이름을 **둘 다** 세고
파일이 명시한 미분류만 제외한다. 변수명도 `defaultCategoryCount` → `uncategorizedCount`.

### 8. `suggestTitle` 이 마크다운 강조를 안 벗긴다 (실측)

PPTX 분석 중 발견. 추정으로 두지 않고 직접 호출해 확인했다.

```
슬라이드 1~10 형식   → "전체 디자인 설정:"
슬라이드 11~33 형식  → "**[AI Instruction: 네온 사인 스타일로…"
첫 줄이 같은 두 문서의 제목이 동일한가 → true
```

- 제목 전부 동일은 **사실** (슬라이드 1~10이 `전체 디자인 설정:` 하나로 수렴)
- **불릿 제거 규칙과는 충돌하지 않는다.** `^[-*+]\s+` 는 `*` 뒤 공백을 요구하는데
  `**[` 에는 없다. 충돌이 아니라 **별표가 그대로 남는** 다른 문제였다

→ T-206(제목 중복 경고) · T-207(강조 표기 제거) 로 등록 (`d1347fe`)

### 9. 검증 도구의 함정 둘

- **`--virtual-time-budget` 은 시계를 얼린다.** `Date.now()` 도 `performance.now()` 도
  0을 돌려줘 성능 측정이 불가능하다. 4번 표는 가상 시간을 끄고 동기 실행으로 다시 잰 것
- **`location.reload()` 가 테스트를 무한 루프로 만든다.** 새로고침 → 프로브 재실행 →
  다시 초기화. 일회성 플래그로 막았다

### 10. 테스트 데이터가 만든 가짜 실패 둘

- T-104e 2차 배치가 등록되지 않아 원인을 팠는데, 테스트 문자열이 **19자**라
  ⚠ 짧음 규칙에 자동 해제된 것이었다. 코드는 정상 — 오히려 T-104d 기본 해제가
  의도대로 동작한다는 확인이 됐다
- T-105 `[reject]` 케이스가 안 돌았는데, `전체 선택`이 **토글**이라 두 번째
  호출에서 선택이 해제된 것이었다

"실패처럼 보이는 것"을 코드 탓으로 돌리기 전에 **재현 조건부터** 확인해야 한다.
