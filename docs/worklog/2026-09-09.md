## 결정사항

### T-104 — 똑똑함보다 예측 가능성

- **구분자 자동 감지를 넣지 않았다.** 대신 **모든 옵션의 분할 개수를 동시에 표시**한다.
  "가장 많이 쪼개지는 것"을 자동으로 고르면 잘못 쪼갤 때 사용자가 눈치채기 어렵다.
  항상 같은 것(빈 줄 2개)에서 출발해야 숫자가 이상한 것을 알아챈다
- **제목은 `placeholder` 가 아니라 `value` 로 채운다.** T-103 단건 폼과 **반대**다.
  150개를 직접 쓰지 않으므로 지우는 마찰이 없고, 23행이 전부 회색 텍스트면
  무엇이 저장될지 스캔할 수 없다. 같은 원칙에서 다른 결론이 나온 사례
- **경고 4종의 기본 체크가 서로 다르다 — 비용 비대칭 때문이다**

  | 배지 | 기본 | 근거 |
  |---|---|---|
  | 짧음(20자 미만) | 해제 | 구분자 실수로 **대량 발생**. 잘못 등록하면 정리 비용이 크다 |
  | 김(5,000자 초과) | 유지 | 정당하게 긴 프롬프트가 있고 대량 발생하지 않는다. 해제하면 **넣으려던 내용이 조용히 빠진다** |
  | 기존과 중복 | 해제 | 같은 소스를 두 번 붙여넣는 것이 가장 흔한 원인 |
  | 조각 내 중복 | 2번째부터 해제 | **첫 번째는 남긴다** — 둘 다 해제하면 내용이 통째로 사라진다 |

- **구분자를 바꾸면 편집은 살아남을 수 없다.** 조각 경계 자체가 달라져
  "같은 조각"이라는 개념이 성립하지 않는다 — 매칭 보존이 원리상 불가능하다.
  보존을 시도하지 않되 **조용히 버리지 않는다**: 확인을 받고, 거부하면
  라디오까지 되돌려 화면과 입력칸이 어긋나지 않게 했다
- 등록 후 **모달 유지, 입력창만 비움** + `이번 세션 N개 등록` 누적 (소스가 3종이라 이어 넣는다)
- 200개 초과는 **막지 않고 경고**. 원인 1순위("구분자를 잘못 고르셨을 수 있습니다")를
  문장으로 지목한다 — 개수만 보여주면 사용자가 원인을 짐작해야 한다

### T-105 — A안: 필터·검색어가 바뀌면 선택을 비운다

"안 보이는 25개가 선택된 채로 남는 것"은 동작이 아니라 결함이다.
**일괄 삭제에도 함께 적용**했다 — 분류는 재분류하면 되지만 삭제는 안 보이는 것이 사라진다.

- `applyFilters()` 맨 앞 **한 곳**에 걸어 진입점 5개(검색·카테고리·즐겨찾기·태그
  클릭·검색기록)를 따로 손대지 않았다
- **정렬은 비우지 않는다.** 순서만 바뀌고 대상 집합이 같다.
  예외 처리가 아니라 **비움 조건을 `filter + query` 로만 정의**해 해결했다
- 비울 때 토스트로 알린다. 선택이 있었을 때만 뜨므로 자기 제한적이다
- 분류 확인은 **1번**. 재분류는 가능하지만 이 동작은 `미분류` 표시 자체를 지운다 —
  잘못 지정하면 어떤 것이 원래 미분류였는지 복원할 수 없다

### T-114 — 버전이 아니라 필드 존재로 분기

- `version` 문자열을 믿고 분기하지 않는다. `Array.isArray(data.categories)` 로
  판단하면 **v1.0 파일은 그 단계가 저절로 건너뛰어진다.** 손으로 고친 파일에서도
  깨지지 않고 분기 코드 자체가 생기지 않는다
- **카테고리 충돌은 id 가 아니라 이름으로 맞춘다.** 프롬프트가
  `p.category === cat.name` 으로 가리키므로, id 로 맞추면 같은 이름이 둘 생기고
  한 프롬프트가 두 카테고리에 동시에 걸린다
- 테마는 `settings` 로 분리하고 **덮어쓰기일 때만 복원**한다.
  병합에서 남의 파일이 내 기기 취향을 뒤집으면 안 된다
- 미분류는 내보내지 않는다 (T-101 불변식 — 관리 화면에서 삭제·수정될 수 없어야 함)

### T-115 — 손상 상태에서 `exportData` 를 쓰면 안 된다

초기화가 중단되면 `allPrompts` 가 비어 있어 **빈 백업이 나오고 사용자는
백업했다고 믿는다.** 그것이 가장 위험한 결과다.
→ `rawBackup` 원본을 그대로 내려받게 한다. 파싱이 필요 없어 손상 상태에서도 항상 된다.

- `removeAll()` 이 `rawBackup` 을 비우므로 **내려받기가 초기화보다 먼저**여야 한다.
  안 받았을 때만 경고를 하나 더 붙여 순서를 UI 로 강제했다
- 초기화는 `removeAll()` + `location.reload()`. 전역을 하나씩 리셋하면
  빠뜨린 하나가 그대로 버그가 된다
- 모달이 아닌 **상단 고정 배너**. 모달은 부분 손상 때 앱을 못 쓰게 만들고,
  배너는 치명적일 때(뒤가 빈 화면) 유일한 조작 대상이 된다

### 자료 이관 — 이미지 소스는 D1 2회차로 분리

- **이미지가 부속물이 아니라 본체인 소스가 있다.** "네온 사인 스타일" 33개를

## 막힌 부분 · 특이건

### `escapeHtml` 은 인라인 `onclick` 을 막지 못한다 (T-111 실측)

가장 중요한 발견. 이스케이프해도 주입이 **실행됐다.**

```
브라우저가 본 속성값: filterByTag('x'); window.__HIT=1; filterByTag('y'); ...
>>> 이스케이프했는데도 주입 실행됨? true
```

HTML 파서가 `&#39;` 를 `'` 로 되돌린 **다음** 그 결과를 JS 로 파싱한다.
T-112에서 세 곳(`prompts.js` 130·172, `search-history.js` 66)이 여전히 뚫리는 것을
확인하고 주석으로 못 박은 뒤, T-113 이벤트 위임으로 구조적으로 닫았다.

**곁가지:** `javascript:` 스킴은 `<img src>` 에서 **실행되지 않는다**는 것도
실측으로 확인했다. T-111 보고에서 부정확하게 말했던 것을 T-112에서 정정했다.
`src=` 의 실제 위험은 스킴이 아니라 `"` 로 속성을 탈출해 `onerror=` 를 붙이는 것이다.

### 150행에서 등록 버튼이 화면 밖으로 (T-104c+d)

```
모달 scrollHeight = 13,705px   clientHeight = 724px
```

목록에만 `max-height: 46vh` + 스크롤을 줘서 **13,705 → 1,189px**. 툴바와
등록 버튼이 제자리에 남는다. 검증하다 발견했다 — 10개로만 테스트했으면 못 봤다.

### 개수와 미리보기의 디바운스 분리 (T-104c+d)

가상 시간을 끄고 실측하니 **150행 렌더가 ~190ms**. 입력마다 다시 그리면
타이핑이 끊긴다. **개수는 즉시(동기), 행 렌더는 180ms 디바운스**로 나눴다 —
구분자를 고르는 판단이 숫자에 걸려 있어 그건 지연시키면 안 된다.

### `renderPromptList` 가 빈 목록에서 카운트 갱신을 건너뛰던 결함 (T-105)

토스트는 `미분류 8개 남음`, 사이드바는 `📥 미분류 (12)`.
빈 목록 분기가 `updateCategoryCounts()` **앞에서 early return** 했다.
필터의 마지막 항목을 분류하면 목록이 비고, 정확히 그 순간 카운트가 멈춘다.
**일괄 삭제에도 있던 결함**이라 함께 고쳤다.

### `parseJSONFile` 이 `thumbnailImage` 도 버리고 있었음 (T-114)

B14는 `notes` 소실이었는데, 조사해보니 썸네일도 함께 버려지고 있었다.
백업을 업로드 영역으로 다시 넣으면 둘 다 사라진다. 같은 결함이라 함께 고쳤다.

### `suggestTitle` 이 마크다운 강조를 안 벗긴다 (실측)

PPTX 분석 중 발견. 추정으로 두지 않고 직접 호출해 확인했다.

```
**[AI Instruction: …]**  →  "**[AI Instruction: 네온 사인 스타일로…"
첫 줄이 같은 두 문서의 제목이 동일한가 → true
```

- 제목 전부 동일은 사실 (슬라이드 1~10이 `전체 디자인 설정:` 하나로 수렴)
- **불릿 제거 규칙과는 충돌하지 않는다.** `^[-*+]\s+` 는 `*` 뒤 공백을 요구하는데
  `**[` 에는 없다. 충돌이 아니라 **별표가 그대로 남는** 다른 문제였다

→ T-206(제목 중복 경고) · T-207(강조 표기 제거) 로 등록

### 검증 도구의 함정 둘

- **`--virtual-time-budget` 은 시계를 얼린다.** `Date.now()` 도 `performance.now()` 도

  다시 초기화. 일회성 플래그로 막았다
