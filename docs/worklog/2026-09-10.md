### ★ D1 1회차 — 실데이터 33건 등록 (코드 작업 아님)

오늘의 출발점. **샘플 3건짜리 사전이 실제로 쓰이는 사전이 됐다.**
T-104(일괄 붙여넣기)와 T-105(일괄 분류)가 어제 갖춰져 가능해진 일이다.

실사용에서 확인된 것 (판단은 [decisions §1·§2](../decisions/decisions-2026-09-10.md)):

- **빈 줄 2개 기본값이 실제 소스에 안 맞았다** — 본문 안에도 빈 줄이 있어(단계 나열,
  문단 구분) 과분할된다. 설계 §2 의 **"전 옵션 개수 동시 표시"가 여기서 값을 냈다** —
  자동 감지였다면 과분할된 개수를 정답으로 골랐을 것이다
- `suggestTitle` 의 한계가 드러났다 — 첫 문장을 30자로 자를 뿐이라
  `"[주제]"에 대한 전자책을 쓰려고 해. 독자들이…` 같은 제목이 여럿.
  **손으로 고치지 않기로 했다** (P4 AI 자동정리가 붙으면 33개를 한 번에 다시 돌린다)

여기서 나온 것이 UI 개선 4건이다. **헤드리스 검증으로는 안 나오는 종류였다** —
스크롤 거리와 반복 횟수는 실제로 손을 움직여 봐야 드러난다.
33장을 눈으로 지나쳐 봐야 "선택 모드 버튼이 그리드 아래에 있다"가 문제로 보인다.

### ★ 프로브가 세 번 거짓말했다

오늘 가장 많은 시간을 먹은 것. **세 번 다 코드는 멀쩡했다.**
원리와 공통 규칙은 [devlog §5.8 · §5.10](../devlog.md) 에 정리했다.

**(1) 고정 `sleep` — 거짓 통과** (T-126)

`--virtual-time-budget` 아래에서 `setTimeout` 은 가상 시계로 즉시 발화하는데
`FileReader` 는 실제 I/O 라 동기화되지 않는다. `sleep(400)` 이 파일 읽기 **전에** 풀려
**작업 전 상태**를 쟀다.

```
패치 전 CASE3  롤백 후 카드=나비,마루,하늘   → PASS   (거짓)
조건 대기로 바꾼 뒤
패치 전 CASE3  롤백 후 카드=자작나무,아침,… → FAIL   (진짜)
```

devlog 에 이 절을 **이미 써 둔 뒤였는데도** 밟았다.
더 나쁜 것은 방향이다 — 거짓 *실패* 는 시끄러워서 결국 파고들게 되지만,
**거짓 통과는 조용하다.** 패치 전 코드에 프로브를 돌려 보지 않았으면 넘어갔다.

**(2) 완료 술어가 작업 경계보다 앞** (T-128)

`catOf('개발A') !== '개발'` 은 `await save*` **이전**의 제자리 변경 직후에 참이 된다.
`currentFilter` 이관과 재렌더가 아직 안 돈 **중간 상태**를 쟀고, 고친 코드가 FAIL 로 나왔다.

로그가 스스로 모순을 드러냈다 — `개발A→미분류` 인데 사이드바는 `💻 개발 (2)`.
삭제가 끝나지 않은 것이다. **완료 신호는 토스트다.**

**(3) 테스트 리터럴이 시드와 어긋남** (T-119)

프로브와 시드를 다른 heredoc 으로 쓰면 한글 리터럴이 안 맞아 거짓 실패가 난다.
한 세션에서 세 번 반복됐다. → **비교 대상을 실제 데이터에서 꺼내 쓴다.**

> 공통 규칙: **관측 지점이 작업 경계보다 앞이면 프로브가 조용히 틀린 답을 낸다.**

### `deleteCategory` 의 `'기타'` 하드코딩 — 자기 자신으로 이동

`p.category = '기타'` 가 문자열 리터럴이었다. 두 경로로 깨졌다.

1. **"기타" 개명** → 이후 다른 카테고리를 삭제하면 프롬프트가 **없는 카테고리**를 가리킨다
2. **"기타" 자신을 삭제** → 자기 자신으로 옮긴 뒤 그 카테고리를 지운다

역검증에서 그대로 재현됐다:

```
패치 전 CASE3  "기타" 삭제 후 고아:
  개발A→기타, 개발B→기타, 기타A→기타, 기타B→기타   (4건 전부 없는 카테고리)
```

삭제 가드도 없었다. **시드 카테고리 이름에 코드가 의존하고 있었던 것**이 근본 원인이다.

- 즐겨찾기를 본 뒤 카테고리를 누르면 **둘 다 켜진 채**로 남았다
  (즐겨찾기 버튼이 `#category-list` 밖이라 해제 대상에서 빠졌다)
- `prompts.js` 3곳은 `querySelector(...).classList` 를 확인 없이 써서
  "전체" 버튼이 없으면 **TypeError 로 함수가 끊겼다**

`syncCategoryActive()` 하나로 모았다. 속성 선택자 대신 `dataset` 비교 —
카테고리 이름에 따옴표가 들어가도 선택자가 안 깨진다.

> 같은 부류를 오늘 두 번 봤다 — 목록 갱신 진입점 7곳(T-126), active 표시 4곳(T-128).
> **한 가지 사실을 여러 곳에서 만들면 언젠가 어긋난다.**

### `transition: all` 이 `visibility` 까지 전이 — 제품 버그였다

헤드리스 **측정** 함정으로 적어 뒀던 것이 제품 코드에도 있었다.
`button { transition: all 0.2s ease; }` 때문에 **숨겨야 할 버튼이 0.2초 동안 클릭 가능**했다.
`.scroll-btn` 의 전이를 색상으로만 한정해 해결. [devlog §5.9](../devlog.md)

### `parseTXTFile` 이 빈 줄을 지워 문단을 훼손하고 있었다

T-121 에서 구분자를 고치다 발견. 옛 코드는 `text.split('---')` 였는데
줄 앵커도 없어 본문의 `a---b` 까지 쪼갰다. **게다가 빈 줄을 제거해**
여러 문단짜리 프롬프트가 한 덩어리로 뭉개졌다.

**CLAUDE.md 의 "본문을 임의로 수정하지 않는다"를 파서가 어기고 있었다.**
구분자 버그를 안 건드렸으면 이건 계속 남았을 것이다.

### `p.title` / `content` / `tags` 가드 부재 — 목록이 통째로 안 그려진다

T-119 로 검색 필드를 늘리다 드러났다. `applyFilters` 의 `filter` 콜백이
필드를 그대로 참조하고 있어, 손으로 고친 백업처럼 **필드가 하나 없는 항목이 섞이면**
`filter` 가 던지고 **목록 전체가 안 그려진다.** 항목 하나가 전부를 가린다.

`(p.title || '')` 형태로 5개 필드 전부 방어. 검색 기능이 아니라 **가용성** 문제였다.
